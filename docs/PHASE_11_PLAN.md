# PHASE 11: The Liability Engine (From Accounting to Responsibility)


## 0. Phase 11의 위치 정의 (Positioining)

Phase 11은 기능 확장이 아니다.
이 단계는 AccountingFlow / AuditFlow가 **‘현실(Reality)’**을 다루기 시작하는 최초의 단계다.

- **Phase 7: 신뢰의 표면 (Trust Surface)**
- **Phase 9: 책임 라우팅 (Responsibility Routing)**
- **Phase 11: 책임의 실체화 (Liability as Reality)**

회계적으로 맞는 장부에서 **살아남을 수 있는 장부**로 이동한다.

## 1. Phase 11의 핵심 질문 (The Core Question)

Phase 11은 다음 질문 하나에 답하기 위해 존재한다.

> **“이 거래는 미래에 어떤 책임을 남기는가?”**

이 질문은:
- 분개 정확성의 문제가 아니며
- AI 판단의 문제가 아니다
- 👉 **경영 책임의 문제다.**

## 2. Phase 11의 목표 (Goals)
🎯 **핵심 목표 3가지**

1. 부채의 ‘발생’이 아니라 **‘존재’**를 인식하게 한다
2. 회계적으로 정상인 상태와 **경영적으로 위험한 상태**를 분리한다
3. **Autonomous Ledger**의 전제 조건을 완성한다

## 3. Liability Engine 정의
### 3.1 Liability란 무엇인가?

Phase 11에서 말하는 Liability는 다음을 포함한다:
- 가수금 (Borrowing)
- 차입금 (Loans)
- 상환 의무가 명확하지 않은 임시 자금
- 사실상 대표 개인의 자금 유입

❗ 단순 계정명이 아니라 **“미래에 현금 유출을 강제하는 구조”**를 의미한다.

### 3.2 Liability Engine의 역할

Liability Engine은 판단하지 않는다. 대신 다음을 수행한다:
- 부채의 발생 순간을 감지
- 상환 계획의 존재 여부를 확인
- 무계획 상태를 **위험 상태(Risk State)**로 표시
- Grey Zone과 연결하여 **침묵(Silence)**을 선택할 수 있음

## 4. 핵심 개념 정의 (System Vocabulary)

### 4.1 Liability State
| 상태 | 의미 |
| :--- | :--- |
| **Planned** | 상환 계획이 명시된 부채 |
| **Unplanned** | 회계상 부채이나 상환 계획 없음 |
| **Deferred** | 상환이 연기된 상태 |
| **Grey Liability** | 판단 보류된 책임 (권한 영역) |

### 4.2 Risk Signal (경고가 아님)
Risk Signal은 에러가 아니다.

> “이 부채는 위험할 수 있습니다.”

- 빨간 경고 ❌
- 자동 조치 ❌
- 판단 강요 ❌

👉 **인지(Recognition)**만 제공

## 5. 가수금(Borrowing) 처리 시나리오

### 5.1 발생 시
- 가수금 계정 발생 감지
- 자동 분개 허용 (차대 불일치 ❌)
- 즉시 다음 질문 생성:
  > **“이 자금의 상환 계획이 존재합니까?”**

### 5.2 상환 계획 없음
- **상태:** Unplanned Liability
- **UI 표시:**
  - 회색 (Grey Zone)
  - 문구: “회계적으로는 정상입니다. 그러나 상환 계획이 확인되지 않았습니다.”
- **시스템 태도:** 침묵(Silence)

### 5.3 상환 계획 입력 (선택)
사용자는 다음 중 하나를 선택:
- 상환 예정일
- 분할 상환
- 대표 판단 보류

⚠️ **자동 실행 없음**
모든 계획은 가시화만 제공

## 6. Trust Surface와의 연결

Phase 11은 Phase 7을 파괴하지 않는다. 오히려 확장한다.

- Liability도 Grey Zone 가능
- Unclassified Liability 존재 허용
- 책임은 항상 사용자에게 귀속

> **“AI는 묻고, 당신은 결정합니다.”**

## 7. Phase 11에서 하지 않는 것 (Out of Scope)

Phase 11은 다음을 의도적으로 하지 않는다:
- ❌ 자동 상환 실행
- ❌ 부채 통합/재분류
- ❌ 은행 자동 연동
- ❌ AI 감사 판정

👉 **이유: 책임이 정의되지 않은 상태에서 자동화는 폭력이다.**

## 8. Phase 11의 성공 기준 (Exit Criteria)

Phase 11은 다음 조건이 충족되면 종료된다:
1. 가수금/차입금이 책임 객체로 인식됨
2. “회계 정상 vs 경영 위험”이 UI로 구분됨
3. Grey Zone 책임 개념이 사용자에게 이해됨
4. Autonomous Ledger의 현실 레이어 완성

## 9. Phase 12 예고 (Not Implemented)

Phase 11 종료 후에만 허용되는 단계:
- **Phase 12: Real Data Integration** (은행 / 카드 / 엑셀)
- **Phase 13: AI Audit** (Risk-Based)
